# 算法离线评测

口味算法的改动都应该先过这里的评测，再合入。三套评测互补：

| 评测 | 数据 | 回答的问题 | 测试类 |
| --- | --- | --- | --- |
| Bangumi15M 真实用户盲测 | 公开数据集抽样的 750 位匿名用户、6.6 万条评分 | 预测分与真实评分的排序一致吗？ | `TasteBangumi15mEvalTest` |
| 个人数据 LOO | 你自己的 Bangumi 评分（本地文件） | 算法像不像**你**？ | `TasteLooValidationTest` |
| 合成用户 LOO | 按假设模型生成的用户 | 改动有没有造成明显退化？（CI 可跑） | `TasteSyntheticLooTest` |

数据文件都放在 `app/build/loo/`（已被 `.gitignore` 的 `build/` 覆盖，不进仓库）；文件不存在时对应测试自动跳过。

## Bangumi15M 盲测

数据集：[Bangumi15M](https://www.kaggle.com/datasets/klion23/bangumi15m)（klion，2023-05-07 快照）。
1500 万条动画收藏记录 + 43 万条目元数据（含带标注人数的标签、社区评分、集数）。用户 ID 已匿名，无短评。

### 1. 下载与抽样

```bash
curl -L -o b15m.zip "https://www.kaggle.com/api/v1/datasets/download/klion23/bangumi15m?datasetVersionNumber=1"
unzip b15m.zip
python3 docs/eval/extract_b15m.py . 500      # 生成 ./eval.json
cp eval.json app/build/loo/bangumi15m-eval.json
```

抽样规则：只取「看过且打了分」的记录；评分数 40–300 的用户抽 500 位、12–39 的抽 250 位
（按用户 ID 的 MD5 排序取前 N，结果可复现）；校准池为收藏数最高的 1500 部动画。

### 2. 运行

```bash
./gradlew :app:testDebugUnitTest          # 约 6 分钟，输出 app/build/loo/b15m-components.tsv
python3 docs/eval/metrics_b15m.py app/build/loo/b15m-components.tsv
```

方法：每位用户的已评分作品分 5 折，轮流用 4 折建画像、把留出的 1 折当「未评分候选」打分——
被预测的作品不在训练集里，没有真实分泄漏。指标按用户分别计算再取平均：

- **Spearman**：预测分与真实评分的排序相关。
- **Top10 命中率**：预测分最高的 10 部里，真实评分 ≥ max(8, 该用户 80 分位) 的比例。

### 3. 当前结果（算法 v5）

| 预测量 | Spearman | Top10 命中率 |
| --- | --- | --- |
| 只用社区评分 | 0.547 | 0.693 |
| 只用画像分（标签口味） | 0.406 | 0.625 |
| 口味匹配度（门控融合，显示用） | 0.487 | 0.669 |
| **预计满意度（推荐排序用）** | **0.561** | **0.708** |

分用户量：评分 ≥40 的用户满意度 0.588 / 0.779，评分 <40 的用户 0.507 / 0.567。

### 4. 试过但没有采用的方案

都在同一份数据上验证过，增益不到 0.01 或为负，故不引入复杂度：

| 方案 | 结果 |
| --- | --- |
| 按「个人评分与社区评分的相关度」给每个人不同的社区权重 | 无增益（0.563–0.565 vs 固定权重 0.567） |
| 用「评分 − 大众基线」的残差建画像 | 混合后持平（0.5635 vs 0.560），但单独的匹配度下降（0.444 vs 0.483） |
| 社区分乘票数置信 `log(votes)/log(20000)` | 下降（0.549 vs 0.562）；因此只对极少票数做贝叶斯收缩 |
| 协同过滤（SVD 物品向量 + 设备端岭回归） | 叠加后仅 +0.008（0.5695），不值得为此随包分发模型 |
| 标签同义归一 | 画像分持平（0.406）；保留是因为语义正确且无副作用 |

结论：就「预测你会打几分」而言，标签画像在社区评分之上只能再解释一小部分，且换成协同过滤也突破不了
——剩下的主要是评分本身的噪声。所以把精力放在**区分两个问题**上：匹配度回答「像不像你的口味」，
满意度回答「看完会不会满意」，推荐排序用后者，再用当晚意图、多样性和跨界名额保证不沦为榜单复读。

### 5. 局限

- 数据止于 2023-05，没有短评、Staff、角色；评论语义维度和实体维度在这里测不到。
- 被评测的是「用户已经选择去看的作品」，比真实候选池整体质量高，社区分的区分度可能被低估或高估。
- 评分是「看完后的满意度」，不等于「想不想看」；探索队列的左右滑行为没有公开数据可验证。
