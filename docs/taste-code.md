# 口味码

把一个人的口味压缩成一段可分享的文本（也能做成二维码），对方在应用里打开后对比两人的口味。
代码在 `domain/tastecode/`（模型、编码、生成、对比，纯 Kotlin）和 `feature/tastecode/`（界面、二维码）。

## 1. 内容

| 字段 | 说明 |
| --- | --- |
| `generatedOnDay`、`algorithmVersion` | 生成日期（epoch 日）、口味算法版本（版本不同时对比照常进行，界面提示仅供参考） |
| `nickname` | 可选，最多 12 字，不填显示「Ta」 |
| `style` | 打分部数、均分、标准差、宽严（均分 − 同批作品社区均分）、跟随口碑程度（个人分歧模型的基线斜率） |
| `dimensions` | 各口味维度（`TasteCategory.key`，不含噪声维度）对这个人的影响：维度默认权重 × 该维度最强 5 个正向标签的平均强度，按最大值归一到 0–1（不用整个维度的权重总和，否则 staff、声优这类标签多的维度会被放大） |
| `liked` / `avoided` | 各维度正 / 负权重按标签合并后的前 24 / 前 12 个，强度 0–1，带分类（`TasteCategory.key`）。按分组配额挑选：题材（题材、组合、情节、改编来源）占一半，角色属性（XP、角色）和创作者（staff、声优）各占四分之一，某组不够时由其它组补；时间标签和梗不进口味码 |
| `divergence` | 个人分歧模型里和大众差得最多的标签（正负各 5 个，单位：10 分制分数） |
| `eraShares` | 收藏按 8 个年代档的占比 |
| `works` | 代表作（Bangumi 条目 id、评分、入选原因）：评分最高 15、和社区分差最大 10、最近评分 5，不重复；用户可逐部去掉 |

不包含短评、账号、完整的收藏列表。

## 2. 编码（`TasteCodeCodec`）

`HSM1.` + Base64url（无填充）。负载是紧凑二进制：魔数 `HSM`、格式版本、变长整数、按单字节量化的数值
（0–1 → 0–255，分数 × 20，斜率 × 50），字符串为长度前缀的 UTF-8，每个标签后跟一个字节的分类编号（`TasteCategory` 的顺序，0xFF 表示没有分类）；末尾附 CRC32 的低 16 位，再用 Deflate（raw）压缩。
满载（30 部代表作）约 600 个字符，二维码用纠错等级 M。解码时校验魔数、版本和 CRC，被截断或改动的口味码返回 `null`。
`extract` 能从链接 `hoshimi://taste/…` 或整段分享文字里找出口味码。

## 3. 对比（`TasteCompatibility`）

契合度只由两份口味码计算，交换双方结果不变（打开方的完整本地数据只用于过滤推荐）。

| 部分 | 计算 | 权重 |
| --- | --- | --- |
| 喜好与雷点 | 喜欢记正、回避记负的标签向量余弦，0.6 以上记满分，负相关记 0 | 0.40 |
| 口味维度 | 维度强度向量的余弦 | 0.15 |
| 年代 | 1 − 年代分布的总变差距离 | 0.15 |
| 打分风格 | 宽严差（3 分记 0）与斜率差（1.5 记 0）的平均 | 0.10 |
| 共同作品 | 1 − 平均评分差 / 5；不足 3 部不计，权重按 部数 / 10 缩小 | 0.20 |

缺少的部分不计入，剩余部分按权重重新归一。

- **称号**（`CompatibilityTier`）按契合度分十档：96 镜像人格、90 天选同担、82 默契老友、74 追番搭子、66 口味相投、
  58 求同存异、50 半路同好、40 有缘人、28 平行世界、其余次元壁两端。
- **相处模式**（`CompatibilityType`）由契合度和打分风格分决定：≥ 80 且风格接近为「同频共振」，≥ 60 且风格差得多为
  「同好不同调」，≥ 60 为「大方向一致」，40–60 且冲突标签不超过 2 个为「互补型」，其余为「各有天地」。
- **标签**：都喜欢的按题材 / 角色属性 / 创作者分组显示；「独爱」= 一方喜欢、另一方既不喜欢也不回避的标签。
- **推荐** = 对方代表作里 8 分以上、我的代表作里没有的作品，界面再去掉我已收藏的。

## 4. 对比页

`feature/tastecode/TasteCompatibilityScreen.kt`：总分和称号、契合度构成（各部分画成雷达图，不足三项时画分数条）、
两人口味维度叠在一张雷达图上（每人按自己影响最大的一项为满格；对方那条用虚线，完全重合时另有说明）、「你们俩」结论、喜好与雷点、共同代表作（评分差 ≥ 2 标「分歧」、
相同标「默契」）和对方的推荐。

「你们俩」由 `CompatibilityInsights` 从两份口味码生成，只用口味码里的数据，所以双方看到的结论互为镜像：

| 结论 | 依据 |
| --- | --- |
| 打分松紧 | 宽严（±0.3 以内算和大众差不多）；两人均分差 ≥ 0.8 时说明同一部作品谁给得高 |
| 爱憎程度 | 评分标准差：≥ 1.8 爱憎分明，≤ 1.1 温和派 |
| 跟不跟口碑 | 跟随口碑斜率：≥ 1.1 很看口碑，≤ 0.6 不太在乎大众评分 |
| 偏爱的年代 | 年代分布的加权平均年份，相差 5 年以上才分早晚 |
| 阅片量 | 打分部数，相差两倍以上时给出倍数 |
| 看重什么 | 各自最强的维度；差距 ≥ 0.25 时说明谁更在意哪一项 |
| 共同作品 | 都放进代表作的部数和评分相差不超过 1 分的部数 |
| 雷区 | 一方喜欢、另一方回避的标签 |
| 共同的小众偏好 | 两人分歧标签同号且都 ≥ 0.2 分：正为都比大众打分更高，负为都更挑剔 |

生成页可以把二维码存成图片（`TasteCodeImage` 画标题、昵称、二维码和用法，`GallerySaver` 写入相册 Pictures/Hoshimi）。
