# Hoshimi 口味算法跟进报告 V6：个人分歧模型

> 适用算法：V6（个人分歧模型）
> 承接：《ACG Compass 最终版算法开发文档》《意图匹配 VNext》《从人类视角重新梳理口味画像的观察维度》
> 范围：评分预测的精度、与大众的分歧（个性化）、算法与应用层代码的配合、AI 提示词、前端适配。
> 验证数据：Bangumi15M 抽样 750 位真实用户、6.6 万条评分；评测方法见 [algorithm-eval.md](algorithm-eval.md)。

## 执行摘要

这份文档回答两个问题：**怎样把评分预测得更准**，以及**怎样让预测不只是社区评分的复读**。

结论是把预测拆成两层，各管各的：

```text
预计评分 = 大众基线（社区评分按你的打分尺度换算） + 个人分歧（你稳定偏离大众的部分）
```

- **大众基线**解决「大多数人对大多数作品的评分跟着社区走」——这是精度的主要来源。
- **个人分歧**只学残差（你的评分 − 基线），回答「这位用户会在哪里、朝哪个方向、因为什么偏离大众」。它由标签分歧、系列一致性、取向维度三部分相加，每一部分都能还原成人话。

在真实数据上，这个结构比上一版明显更准，而且每一分的偏离都有出处：

| 版本 | Spearman | Top10 命中率 | 说明 |
| --- | --- | --- | --- |
| 只用社区评分 | 0.547 | 0.693 | 基准 |
| V5 预计满意度（社区 + 12 维画像混合） | 0.561 | 0.708 | 前一版算法 |
| **V6 个人分歧模型** | **0.603** | **0.740** | 评分 ≥40 部的用户为 0.638 / 0.818 |

预测评分与真实评分的平均绝对误差 0.69 分，相差 1 分以内的占 77%。在「用户与大众相差 2 分以上」的评分里（占全部评分的 5.9%），模型对偏离方向的判断正确率约 70%。

之前的文档里有不少设计停留在纸面。V6 先清点了应用层实际拿得到什么、哪些拿到了却没用，再决定算法怎么写——下面第一节就是这份清点。

## 二、数据怎么说：分歧能不能预测

先在 Python 里把候选方案都试了一遍（每位用户 5 折；各部分的系数在一半用户上拟合、在另一半用户上检验，下表是检验那一半的结果）：

| 预测量 | Spearman | Top10 命中率 |
| --- | --- | --- |
| 只用社区评分 | 0.539 | 0.688 |
| + 相似作品近邻的平均残差（kNN） | 0.595 | 0.726 |
| + 残差对标签的岭回归 | 0.601 | 0.732 |
| + 系列一致性 | 0.603 | 0.734 |
| + 取向维度（热门程度 / 年代 / 篇幅 / 争议度） | 0.607 | 0.739 |
| + 想看 / 抛弃等收藏状态 | 0.606 | 0.736 |

几个判断直接来自这张表：

1. **「分歧」是可预测的，而且主要藏在题材里。** 单是「残差对标签做岭回归」这一项就把 Spearman 从 0.539 提到 0.601。上一版用的启发式画像（按评分累加标签权重）在同样的数据上只多出 0.014——同样的信息，换成正经的回归，效果差了四倍。
2. **系列一致性有效但覆盖有限**（约 10% 的评分有同系列前作），所以增量不大，但对续作很准。
3. **收藏状态对预测评分没有帮助。** 想看、抛弃反映的是兴趣，不是看完后的满意度。这正是第三份文档强调的区分，数据支持它。
4. **按收藏更新时间加权没有增益**，印证了「更新时间不等于观看时间」的担心。

## 三、模型

### 3.1 大众基线

```text
baseline(x) = 你的均分 + slope · (社区分(x) − 你看过作品的平均社区分)
```

`slope` 由你的评分对社区评分做最小二乘，再向全站先验 1.0 收缩（先验强度 15 部）。评分少时接近 1，评分多时接近你自己的斜率。它同时给出两个可读的个人特征：

- **打分宽严** = 你的均分 − 这些作品的社区均分。
- **跟随口碑** = slope。大于 1.25 表示口碑好坏对你的影响比大众更大，小于 0.6 表示你不太看口碑。

### 3.2 标签分歧

把每部作品表示成标签向量：去掉年代、媒介格式、自身标题等噪声标签，同义归一，权重取 `sqrt(标注人数份额) · idf`，再做 L2 归一。然后对残差做岭回归：

```text
(K + λI) · a = residual        K = X·Xᵀ，λ = 1
w = Σ aᵢ · xᵢ                   还原成每个标签的权重
标签分歧(x) = w · x
```

用核形式求解是因为样本数（最多 300）远小于标签数；解出来再还原成每个标签的权重 `w`，预测时只需要一次稀疏点积，而且 `w` 本身就是解释：权重 +0.4 的意思是「带这个标签的作品，你通常比大众水准多给 0.4 分」。

### 3.3 系列一致性

```text
系列分歧(x) = 0.32 · Σ同系列已评作品的残差 / (n + 0.5)
```

系列键沿用探索队列 / 今晚看什么已有的归并规则（剥掉「第二季 / Season 2 / 剧场版」等标记）。

### 3.4 取向维度

残差对三个作品属性做一个很小的岭回归（λ = 8），再以 0.33 的系数并入：

| 维度 | 特征 | 读法 |
| --- | --- | --- |
| 热门程度 | ln(1 + 评分人数) − 8 | 偏爱大众热门作，还是小众冷门作 |
| 年代 | (年份 − 2012) / 8 | 偏爱新番还是老番 |
| 篇幅 | ln(1 + 集数) − 2.5 | 偏爱长篇还是短篇 |

实验里还有第四个维度「争议度」（社区评分分布的标准差）。应用目前没有存这个字段，四个维度合计的增益约 0.004，为它加一次数据库迁移不划算，所以没有实现。

### 3.5 合成

```text
预计评分 = clip(baseline + 标签分歧 + 系列分歧 + 取向分歧, 1, 10)
预计满意度 = 50 + 45·tanh(((预计评分 − 你的均分) / 你的评分标准差) / 1.5)
```

带社区评分的已评分作品不足 8 部时不建模，退回 V5 的「社区 + 画像」口径。

### 3.6 与「口味匹配度」的关系

| | 口味匹配度 | 预计评分 / 满意度 |
| --- | --- | --- |
| 回答的问题 | 这部像不像你常看、爱看的类型 | 你看完会打几分 |
| 模型 | 12 维画像 + 门控社区融合 | 大众基线 + 个人分歧 |
| 用在哪 | 详情页百分比、口味阈值过滤 | 今晚看什么与探索队列的排序、详情页预测块 |
| 真实数据 Spearman | 0.487 | 0.603 |

一部口碑极好的陌生题材，匹配度不高而预计评分高——两个数字同时展示，界面上用不同的措辞区分。

## 四、兴趣信号：左右滑与收藏状态

数据说它们对预测评分没用，但你希望它们对画像有轻微影响，这两件事并不矛盾：它们影响的是「像不像你会想看的东西」，所以进**口味匹配度的画像**，不进评分预测。

| 信号 | 偏好值 | 权重 |
| --- | --- | --- |
| 想看 | +0.25 | 0.4 |
| 在看（未评分） | +0.30 | 0.4 |
| 搁置（未评分） | −0.15 | 0.4 |
| 抛弃（未评分） | −0.50 | 0.5 |
| 探索队列：加入待补池 | +0.25 | 0.4 |
| 探索队列：暂不 | −0.10 | 0.3 |

单条信号的强度不到一条正式评分的四分之一；只影响题材、情节、角色类型、来源四个内容维度；不参与校准、不参与组合挖掘、不计入样本数；已评分的作品以评分为准。探索队列的滑动回看半年。

**这一部分没有数据验证**——公开数据集里没有 Hoshimi 的滑动行为，权重是按「明显弱于评分」定的，属于设计判断。

## 五、AI：让它在证据上做归因

之前的 AI 口味匹配拿到的是作品标签、简介、几条高分低分作品和一串高低分标签，然后被要求「给出契合度」。它没有任何依据判断这位用户会不会偏离大众，只能凭标签印象打分。

V6 把本地模型的结果作为证据交给它：

```text
【本地模型】该用户均分 7.4，比同批作品的社区均分高 0.2 分
大众基线 7.6，预计评分 8.3（个人分歧 +0.7）
分歧来源：悬疑 +0.4、群像 +0.2、小众冷门作 +0.1
【题材相近的已评分作品】
- 作品 A：你 9 分，大众基线 7.8（+1.2），短评：伏笔回收得漂亮
- ……
【与大众分歧最大的评分】
- 作品 B：你 4 分，大众基线 7.9（−3.9），短评：结局完全崩了
- ……
```

提示词相应重写为四步：从分歧最大的评分和短评里归纳用户的**评分角度**；看相近作品里他通常比大众高还是低；判断本作是否触发；给出预计评分。并且写明约束：证据不足时不得偏离大众基线超过 0.5 分。

输出新增三个字段：`predictedRating`（预计评分）、`divergenceReason`（一句话说明为什么会比大众高 / 低，必须引用证据）、`ratingAngles`（打分最看重的角度）。旧缓存缺这些字段时界面不显示，不会报错。

这样分工：**本地模型负责「偏多少」**（有数据验证），**AI 负责「为什么」**（读得懂短评，能说出「你在意结局收不收得住」这种本地模型说不出的话）。

AI 这部分我没有 API Key，**没有实际调用过**，提示词的效果需要你用自己的 Key 试。

## 七、界面与走查

前端新增三处展示，都只在模型可用时出现：

- **详情页**：口味匹配度下方的预测块——预计你会打几分、大众基线、个人分歧，一句话结论，以及分歧归因标签。已评分的作品不显示。
- **口味画像页**：「你和大众的分歧」——打分宽严、跟随口碑、分歧幅度、比大众更偏爱 / 不如大众买账的题材、取向维度的结论。
- **探索卡片与今晚推荐理由**：带上预计评分。

这个环境没有设备也跑不了模拟器，所以新增了一套 **JVM 内的界面走查**（`ScreenWalkthroughTest`，Robolectric 原生渲染 + Compose UI Test）：把页面真实画出来，按操作顺序点一遍并断言每一步的状态，同时截图。覆盖了：

- 今晚看什么：选时间 → 选标签 → 切候选池 → 开单一推荐 → 生成 → 看到三档结果 → 点卡片进详情 → 返回。
- 探索队列：翻面看简介 → 按钮加入 → 右滑加入 → 暂不 → 完成页统计 → 再来一批。
- 预测块与分歧画像：浅色、深色各渲染一次。

走查过程中靠截图发现并修掉了四个问题：中性色标签在卡片上没有底色、分歧为 ±0.0 的标签被展示、来源写成全大写、跨界卡片「可能感觉一般」与预计 8.1 分互相矛盾。

它验证不了的：真机上的滑动手感、动画流畅度、网络请求、AI 调用，以及 ViewModel 与数据库的真实联动。

## 八、局限与下一步

**没有验证的部分**

- 隐式兴趣信号的权重、AI 提示词的效果、Staff / 声优在分歧模型里的作用——都没有可用的数据。
- 评测集是「用户已经选择去看的作品」，真实候选池的整体质量更低，社区分的作用可能不同。
- Release 包没有在真机上启动过。

**下一步值得做的**

1. **观看进度**（`progress`）：看了一半没评分的作品，可能比「抛弃」这个状态更能说明问题。目前完全没用。
2. **评分变更历史**（时光机快照）：改过分的作品说明你对它有过犹豫，可以降低它在训练里的权重。
3. **把 AI 归纳的评分角度存下来**，在口味画像页汇总展示，而不是只在单部作品的分析里出现。
4. **三个没有调用点的 AI 任务**：接上，或者删掉提示词和 schema。
5. **真实观看时间**：拿不到之前，建议把 12 维画像的时间半衰期调长。
